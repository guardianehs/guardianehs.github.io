EHS software fails where the work happens

Arun Williams · 5 min read

Every safety application I have used was demonstrated in a meeting room with full Wi-Fi. Then it goes to a basement plinth, a plant room behind a metre of concrete, or a site three hours from the nearest tower — and it becomes a white screen with a spinner. The places where safety matters most are, reliably, the places with no signal.

Offline as a requirement, not a feature

So Guardian was built backwards from that constraint. The default state is disconnected, and the connection is the bonus. In practice that meant three decisions:

  • No build step and no server. The app is plain HTML, CSS and JavaScript in one file. It can be opened from a phone, a laptop, a memory stick or a box on your own network.
  • A service worker for the launch. Once installed, the app opens with no signal at all, because the shell is already on the device.
  • A reference engine that needs no model. Fifty EHS topics with exact calculators — risk scoring, LTIFR and TRIR, gas limits, depth and height thresholds — all computed on the device.

The part people miss: an offline answer must be exact

When a model is unavailable, the temptation is to return something vague and hedge. That is useless at a work front. So the offline engine computes rather than recalls: give it 640 workers and it returns the number of first-aid boxes and the ambulance-room threshold; give it o2 18.2 lel 3 and it refuses the entry with the reason. Deterministic answers are the only kind worth shipping without a model behind them.

Being offline should change how much you get, not whether you can trust it.

What it cost

Plenty. Files attached while offline live only in that session, because a browser cannot sensibly hold arbitrary documents forever. Cloud sync obviously waits for signal. And keeping everything in one file means discipline about size — every feature is weighed against load time on a bad connection.

Where the connection does earn its place

Two things genuinely need it, and both are now live: a model of your choosing for open-ended questions, and the organisation database — so a permit decision made in the site office appears on the requester's phone the moment it is taken, and the register a colleague updated is already correct when you open it. Everything else keeps working while you wait for a bar of signal.
